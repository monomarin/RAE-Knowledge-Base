# Documentation Standards

> Official documentation standards for RAE Platform.

---

# Executive Summary

This document defines the mandatory standards for creating, maintaining and evolving documentation within RAE Platform.

Documentation is considered a first-class engineering artifact and follows the same governance, quality and review processes as source code.

---

# Vision

Create documentation that remains accurate, discoverable, maintainable and valuable throughout the platform lifecycle.

---

# Documentation Principles

Every document must be:

- Clear
- Accurate
- Complete
- Consistent
- Versioned
- Traceable
- Searchable
- AI Ready
- Maintainable

---

# Documentation Types

Supported documentation includes:

- Architecture
- Product
- Business
- Security
- AI
- Infrastructure
- APIs
- Runbooks
- ADRs
- Standards
- Tutorials
- Reference Guides

---

# Document Structure

Every document includes:

- Metadata
- Executive Summary
- Objectives
- Scope
- Main Content
- References
- Related Documents
- Approval Status

---

# Metadata

Mandatory metadata:

- Document ID
- Title
- Version
- Status
- Category
- Owner
- Release
- Domain

---

# Writing Standards

Documentation must:

- Use simple language.
- Avoid ambiguity.
- Explain terminology.
- Prefer active voice.
- Separate facts from recommendations.
- Use consistent terminology.

---

# Formatting Standards

Use:

- Markdown
- Headings
- Tables
- Bullet Lists
- Code Blocks
- Diagrams
- Cross References

Maintain consistent formatting across all repositories.

---

# Diagrams

Approved formats:

- Mermaid
- PlantUML
- C4 Model
- BPMN
- Sequence Diagrams
- ER Diagrams

Diagrams must remain version controlled.

---

# Cross References

Every document links to:

- Related standards
- Architecture documents
- ADRs
- APIs
- Knowledge assets

Broken references are not allowed.

---

# Versioning

Every modification updates:

- Version
- Change Log
- Review Date
- Approval Status

Historical versions remain accessible.

---

# AI Documentation

AI-generated documentation must:

- Follow official templates.
- Include traceability.
- Be reviewed by humans.
- Pass documentation validation.
- Preserve terminology consistency.

---

# Documentation Review

Every document is reviewed for:

- Technical Accuracy
- Completeness
- Consistency
- Readability
- Architecture Alignment
- Cross References

---

# Documentation Lifecycle

Draft

↓

Review

↓

Approved

↓

---

# Success Criteria

Documentation standards are successful when:

- Documentation remains current.
- Teams easily discover information.
- AI agents understand project knowledge.
- Documentation quality remains consistent.
- Knowledge loss is minimized.
